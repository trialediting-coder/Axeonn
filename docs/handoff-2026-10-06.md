# Handoff: client onboarding portal, admin move, and what is next

Written 2026-10-06 at the end of a Claude Code web session so a local session
can pick up with full context. Read this first, then `docs/onboarding.md`.

## The problem we are solving

Axeon sells low-ticket, high-volume plans to local service businesses
(Essentials $149/mo, AxeonCORE $299/mo, AxeonGROWTH $999/mo, see
`data/pricingData.ts`). Onboarding was a slow email back-and-forth: collecting
Google access, logins, photos, hours, phone routing. At these prices that has to
be structural, not manual.

## Decisions made with the owner

1. **Sort every item into three buckets.** Axeon does it (GA4, Search Console,
   hosting, forms, reports: client never asked). Accept the platform invite
   (GBP, calendar, Google Ads, Meta: one button). Confirm a prefilled card
   (business details, services, lead routing, phone setup, sales process).
   Launch never waits on any client item.
2. **GA4 alone does not show results.** What matters for a local business:
   GBP insights (calls, directions), call tracking, form and booking events,
   local rank tracking, Search Console, and ad conversions. All of these are
   Axeon-controlled infrastructure except GBP access. Reporting should lead
   with calls, leads and map rank, not sessions.
3. **A portal on the site, one token per client**, not a Typeform. Token is
   the credential; no login to forget.
4. **Security:** 20-char token, 6-digit email code on each new device (hashed,
   10 min, single use, 5 tries, 60s cooldown, 12 sends), signed 30-day device
   cookie, per-IP limits, masked phone numbers once saved, read-only 60 days
   after completion, generic 404 for bad tokens. IP locking was rejected
   (mobile IPs rotate). Passwords are never collected; a test enforces it.
5. **Admin moved from `/insights/admin` to `/admin`** with permanent redirects.
6. **Next: `app.axeonstudio.co`** for admin, portal and pay, same Next.js
   project, host-based middleware routing. Owner has already added the Vercel
   env vars `APP_URL=https://app.axeonstudio.co` and
   `AUTH_URL=https://app.axeonstudio.co/api/auth` (Production only, type
   Config). DNS CNAME and domain-in-Vercel status unknown at handoff. Code for
   host routing is NOT written yet.
7. **Later: one token for the whole client lifetime.** Mint the client record
   when the pay link is minted, show "Pay your deposit" as the first portal
   item, add a Billing section using the Stripe Customer Portal, redirect old
   8-char `/pay/<token>` links. Skip the email code for the payment view only.

## What is live on `main` (merged and pushed, commit e592687)

- `/welcome/<token>` client portal: `app/welcome/[token]/page.tsx`,
  `components/welcome/VerifyCode.tsx`, `components/welcome/OnboardingPortal.tsx`.
- Public API: `app/api/welcome/[token]/{code,verify,items}/route.ts`,
  helpers in `lib/welcomeApi.ts`.
- Core: `lib/onboarding.ts` (tokens, codes, cookie, validation, Postgres),
  `lib/onboardingFulfillment.ts` (purchase → portal + welcome email,
  idempotent per checkout session and per email, upgrades tier on a higher
  purchase), `data/onboardingItems.ts` (all items and fields).
- Stripe webhook calls `startOnboarding()` on paid/processing Checkout when
  `metadata.tier` or `metadata.plan_key` maps to a plan. Mail failures are
  logged, never retried through Stripe.
- Emails in `lib/email.ts`: welcome, verification code, nudge. From
  `RESEND_CLIENT_FROM_EMAIL` or `Axeon Studio <hello@axeonstudio.co>`.
- Admin: `/admin/onboarding` board (`components/insights/OnboardingBoard.tsx`)
  and `/admin/onboarding/<token>` detail (`OnboardingDetail.tsx`); API
  `app/api/admin/onboarding/*` (list, mint by hand, mark item done/reopen,
  resend welcome, nudge, close/reopen).
- Tables `onboardings` and `onboarding_items` created by `ensureSchema()` in
  `lib/db.ts` and by `scripts/init-db.mjs`.
- Marketing chrome hidden on `/welcome/*` via `hidesSiteChrome()` in
  `lib/adFunnel.ts`.
- Tests: `npm run test:onboarding` (16 tests). Typecheck and build were green.

## Open work, in the order we discussed

1. **app.axeonstudio.co host routing** (owner env vars already set).
   Middleware: app host serves `/admin`, `/welcome`, `/pay`; main domain
   redirects those paths to the app host; app host redirects everything else
   to the marketing site. No Header/Footer/popups, no GA4 or Apollo tracker
   on the app host (both are in `app/layout.tsx`). Links in emails and
   `welcomeUrl()` / `payLinkUrl()` build from `APP_URL`, falling back to
   `SITE_URL`. Robots: disallow all on the app host, drop the admin disallow
   from `public/robots.txt`. Keep `/insights/admin` → `/admin` redirects.
2. **n8n nudges**: days 1, 3, 7 for open client items. The admin API already
   exposes list (`GET /api/admin/onboarding`, bearer `CMS_API_TOKEN`) and
   nudge (`POST /api/admin/onboarding/<token>` with `{ "action": "nudge" }`).
   A scheduled n8n flow can read the list, filter `status = active` with
   `lastClientActivityAt` older than N days and `nudgeSentAt` not in the last
   48h, and call nudge. Also internal tasks on creation: send GBP request,
   create GA4 property, order tracking number.
3. **Airtable mirror**: n8n copies each onboarding and completed item to the
   base the lead webhook already writes to (`LEAD_WEBHOOK_URL` →
   hayderaxeon.app.n8n.cloud). Keep the `SERVICES` values in
   `data/getStartedPackages.ts` in sync with the Airtable "Services" field.
4. **Photo and logo upload** via Vercel Blob (`@vercel/blob`), private store,
   signed URLs for admin, strip EXIF GPS before publishing. Today the client
   texts photos and taps "Sent them".
5. **Prefill from the client's existing GBP listing** (Places API) so confirm
   cards start filled.
6. **Single token for pay + portal + AxeonPROOF** (decision 7 above).
